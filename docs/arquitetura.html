Arquitetura do Controle de Estoque

O projeto segue a Clean Architecture: as regras de negócio do estoque ficam no centro e não sabem nada sobre HTTP, HTML ou banco de dados. Cada camada externa depende apenas das camadas mais internas.

A regra de dependência

O código só pode importar camadas mais internas

Um handler HTTP pode chamar um caso de uso. Um caso de uso nunca importa um pacote HTTP ou SQL. Para chegar ao banco, o caso de uso usa uma interface definida no domínio, e a infraestrutura fornece a implementação.

cmd / web → delivery · infrastructure → usecase → domain

Com isso você pode trocar o banco (SQLite → Postgres) ou o front (templates → API JSON) sem mexer nas regras do estoque, e testar os casos de uso com repositórios falsos em memória.

Cada camada, de dentro para fora

Domínio

Entidades e contratos
internal/domain/entityinternal/domain/repository

O coração do sistema. Aqui ficam as entidades do estoque e as regras que valem sempre, como "a quantidade de um produto nunca fica negativa". Também ficam as interfaces de repositório, que dizem o que precisa ser salvo, mas não como.

  • entity: Produto, Movimentacao (entrada/saída), Categoria
  • repository: ProdutoRepository com Salvar, BuscarPorID, Listar
  • Não importa nada além da biblioteca padrão.

Casos de Uso

Regras da aplicação
internal/usecase

Cada caso de uso é uma ação que o usuário faz no sistema. Ele coordena entidades e repositórios para cumprir a tarefa, recebendo os repositórios por injeção de dependência.

  • Cadastrar produto, registrar entrada, registrar saída, listar estoque baixo
  • Depende só de domain. Não sabe se foi chamado por uma página web, uma API ou um teste.

Adaptadores

Entrada e saída
internal/delivery/http/routerinternal/delivery/http/handlerinternal/infrastructure/repositoryinternal/infrastructure/database

Traduzem o mundo externo para a linguagem do domínio e vice-versa.

  • delivery (entrada): o router registra as rotas e o handler lê o formulário, chama o caso de uso e renderiza o template HTML.
  • infrastructure (saída): database abre a conexão; repository implementa as interfaces do domínio com SQL.

Frameworks e Drivers

Detalhes técnicos
cmd/serverweb/templatesweb/static

A borda do sistema: ferramentas e arquivos que podem ser trocados sem afetar o negócio.

  • cmd/server/main.go: ponto de entrada e composition root. Cria o banco, os repositórios, os casos de uso e os handlers, e liga tudo.
  • web/: o front em Go, com templates html/template e CSS.
  • net/http e o driver do banco de dados.
